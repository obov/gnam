# workflow: experiment (ept)

목적은 요청된 작업을 재료로 agent 배치·분할·인계·검토·세션 정책의 효과를 검증하는 것. 구현 이력은 GNAM 기존 규약, 실험 근거는 [GNAM experiments](../../gnam-ept/references/experiments.md). 이 모드는 일반 작업의 runner/reviewer 절차를 자동 적용하지 않는다.

## 완료 작업도 실험 과제로 사용

GNAM의 Git 이력으로 작업 이전의 실제 코드와 당시 요구·검사를 복원해, 제품 작업 완료 뒤 전략을 따로 검증할 수 있다. 완료된 plan/run/merge가 대상이면 [replay-experiment.md](replay-experiment.md)를 먼저 읽는다. 당시 구현 전 base에서 재수행하며 원 완료 상태는 참고/평가 근거로 구분한다. 역사적 비용 비교와 현재 환경의 짝 재실행을 구별하고, 군별 최종 코드도 정리 후 복원할 수 있도록 Git에 보존한다.

## 요청 해석과 설계

먼저 사용자 원문과 확정 조건을 보존한다. 작업 목표와 연구 질문을 구분한다. 조건이 충돌하거나 예산·완료 기준이 실행에 부족하면 그 항목을 확인한다. 이미 정해진 조건·승인을 다시 묻지 않는다.

조건이 부족하거나 사용자가 설계를 요청하면 **실행 없이** 요청에 맞는 설계안 2–3개를 제시한다. 무조건 모든 조합을 실행하지 않는다. 각 안은 아래를 포함한다.

- 질문·가설: 무엇이 좋아질 것으로 예상하고, 어떤 결과면 그 가설을 지지하지 않는가.
- 기준군·비교군: 역할/부모/보고 대상/권한/업무 분할/의존/검토/새 세션 또는 재사용.
- 바꿀 변수와 고정 조건: model·effort는 기록하며 구조 비교에서는 가능한 한 고정. 사용자 지정 모델 비교라면 구조를 고정. 여러 변수를 바꾸면 묶음 비교로 명시.
- 실제 완료·품질 기준, 비용·시간·조정 부담 측정, 시작 코드·입력·평가 방식.
- 범위·최대 동시 세션·시도 수·시간·중단 조건·산출물 반영 여부. 토큰/금액 예산은 측정·차단 수단이 있는 경우에만 보장.
- 추천안과 이유, 현재 불확실성과 추가 실행 비용.

다양한 안의 예: 단일 대 분할 병렬 / root 직접 조정 대 delegator / 기존 세션 대 새 세션+작은 인계. 요청과 관련 있는 것만 선택한다. 단일 기준군에도 형식적인 reviewer를 추가하지 않는다. 사용자 조건이 완결된 실행 요청이면 그 조건을 구체적인 설계로 기록하고 진행한다. 새로운 비교군·범위·예산 확대는 승인된 실행에 섞지 않는다.

## 실행

1. record.json을 `proposed`(제안) 또는 `ready`(확정)로 기록. 확정의 근거를 approval에 남긴다. 예산·중단 조건과 완료 기준을 실행 전에 검사한다.
2. 기준군과 비교군은 동일 시작 커밋의 별도 checkout/worktree와 고정 입력으로 준비. 실행 순서·캐시·기존 결과 노출·기존 세션 경험을 기록. 같은 작업의 반복은 학습/노출 오염 가능성이 있으므로 순서를 바꾸거나 새 세션을 사용하고 한계를 남긴다.
3. 실험 지시에 `mode=ept`, experiment/arm/task/attempt ID, 역할·권한·보고 대상·완료 기준·입력 참조·수정 범위를 포함. 기존 roles 문서를 사용할 때 실험 설계와 충돌하는 작업 전용 기본값을 적용하지 않는다. 제품 구현을 포함하면 기존 spec·plan 규약은 유지.
4. prepare/start/prompt/wait/read/close는 harness-execute를 사용. 실제 전달 확인과 제출·검증을 구분하고 root 포함 사건을 기록. 모델 자동 상향·탐색·추가 리뷰·새 agent 추가는 하지 않는다. 필요한 변경은 이유와 사건을 남기고, 비교 조건을 바꾼 시도는 분리한다.
5. root가 사건 기록의 단일 작성자. 자식은 구조화된 보고를 부모에게 반환. 재위임은 설계·상한 내에서만. 하위 비용은 최상위 record에 각 시도를 한 번만 집계한다.
6. 정착 상태+완료 보고+고정 산출물+검증 근거를 대조. idle/파일 존재만으로 완료 판정 금지. 반려·재시도·막힘·미실행·중단도 보존. 미확정 전달은 무조건 재전송하지 않고 실제 상태부터 확인.
7. 군별 결과와 root의 전달·검수·판단·통합·예외 비용을 남긴다. rebase 충돌·재설명·중복 작업은 구조 비교의 결과일 수 있어 noise로 자동 제외하지 않는다. 측정 누락은 null, 분모 0은 미측정.
8. 종료/중단 때 record 검사 → 근거와 함께 chore 커밋 → 임시 트리/세션 정리. 정리 전에 배치와 변경 사건을 영구 보존. 승인된 제품 반영만 기존 검사·리뷰·통합 절차로 진행하며, 이 비용은 실험 수행 비용과 구분.

## 판정

품질/완료 기준 충족을 먼저 보고 완료까지 시간·전체 관측 비용·root 부담·인계 실패·재작업·후속 결함을 함께 비교한다. 수정 횟수나 agent 수 자체는 성과가 아니다. 리뷰 발견은 내용·수용/기각 이유·수정 확인을 남기되, 발견 0건을 reviewer 실패로 판정하지 않는다.

단일 실행은 작동 확인. 통제하지 못한 변수·노출·예산 중단·미측정 비용을 명시한다. 결론은 적용 조건을 가진 유지/변경/판단 보류. 실험 결과만으로 일반 작업 정책을 자동 변경하지 않는다. 후속 반복이 뒷받침하면 lore로 정리하거나 스킬/검사 변경을 별도 수행한다. story-teller 기록은 가설의 근거이며 확정된 생산성 효과로 사용하지 않는다.
