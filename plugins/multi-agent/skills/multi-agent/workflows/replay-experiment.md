# ept — 완료 작업의 Git 이력 재실험

GNAM의 Git 이력은 작업 이유와 당시 실제 코드·spec·검사·lockfile을 함께 보존한다. 작업을 끝낸 뒤에도 **변경 전 상태에서 같은 과제를 다른 agent 전략으로 다시 수행**할 수 있다. 제품 작업의 납기와 workflow 연구의 시점을 분리하고, 완료된 작업을 재사용 가능한 실험 과제로 만든다.

이 문서는 [experiment.md](experiment.md)의 사후 실험 방식이다. 단순 최종본 재검사와 구현 과제 재수행을 구분한다. 사용자가 `multiagent ept 완료한 <작업/plan/run>을 다른 전략으로 비교해줘`라고 요청하면 읽는다. 대상만 지정하고 조건이 없으면 아래 복원 결과를 바탕으로 설계안을 제안한다. 실제 재실험 요청과 조건이 확정돼 있으면 범위 안에서 실행한다.

## 1. 실험 과제로 복원

기존 GNAM을 역추적한다: plan → impl의 Plan/단계 → merge → run.start/end → 당시 spec/요청/판단/검사. 이름이나 HEAD~1로 시작점을 추정하지 않는다. root가 다음을 명시한 `replay-manifest.json`을 실험 증거로 보관하고 record.json의 evidence에 경로·SHA-256을 등록한다.

| 항목 | 기록 내용 |
| -- | -- |
| source | 원 작업 plan·단계·run·impl·merge의 확보한 전체 commit hash, 미확보 항목은 null과 이유 |
| base_commit | 선택한 과제를 구현하기 **전**의 코드 전체 상태. 선택 이유, 선행 단계가 포함되는지 |
| reference_commit | 원 작업의 완료 상태. 여러 merge로 끝났다면 목표 범위를 포함한 최종 commit |
| task_snapshot | 당시 요청·spec·완료 조건·범위·입력의 commit:path 또는 고정 증거 ID. 당시 이후 변경과 구별 |
| evaluation | 모든 군에 동일하게 적용할 검사·독립 품질 평가, 버전·입력·기준·평가자 노출 |
| environment | 런타임/하네스/모델 요청·관측, lockfile·설치 방법, 외부 데이터·캐시·병렬 부하의 확보 범위 |
| strategy | 원래 구조를 복원할 근거·미확인 부분, 비교할 새 구조, 사용할 스킬/역할/prompt 판 |
| exposure | root·작업자·평가자가 이미 본 원 구현/후속 코드/리뷰/결함과 차단 방법 |
| retention | 군별 작업 브랜치·최종 commit·영구 ref/tag 또는 Git bundle 증거, 정리 후 복원 방법 |

`base_commit`과 `reference_commit`은 `git rev-parse <ref>^{commit}`으로 전체 hash를 확인한다. 보통 대상 merge의 첫 부모가 후보지만, 그때 다른 병렬 결과가 이미 들어왔다면 원 작업 착수와 동일하지 않다. 여러 단계 과제는 범위의 시작점을 직접 고른다. 해당 저장소에서 source/ref 객체 존재·선후/조상 관계와 `git diff <base> <reference> -- <범위>`를 확인하고, 요구사항이 base에 있는지 점검한다.

원 plan·요청이 코드 시작점 이후의 커밋에 있으면 **그 요구사항만** commit:path에서 별도 추출해 동일하게 전달한다. 완성 코드·후속 impl Decisions·리뷰 정답까지 입력에 섞지 않는다. 모호했던 요구를 지금 명확하게 바꿨다면 당시 작업 재현이 아니라 '요구 보강 조건의 비교'라고 이름 붙인다. 공개 repo의 Git history 접근을 prompt만으로 차단했다고 주장하지 않는다.

## 2. 비교 설계

다음 세 방식을 구별하고 질문에 맞는 것을 고른다.

| 방식 | 목적과 한계 |
| -- | -- |
| 원 실행 기록 대 새 전략 실행 | 저비용 탐색. 원 결과·비용의 확보 범위와 시대/환경 차이를 명시. 역사값 누락을 0으로 채우지 않으며 구조의 인과 효과로 단정하지 않음 |
| 원 전략 재실행 대 새 전략 재실행 | 같은 base·요구·현재 환경에서 구조 비교. 원 전략의 불명확 부분은 복원 가정으로 남김. 재실행 기준군과 역사적 실제 실행을 별개로 기록 |
| 여러 완료 과제에서 짝 비교 | 적용 조건 탐색. 각 과제는 자기 base·동일 평가로 군을 비교. 과제별 결과·규모·의존성·판단량을 유지하고 총합만으로 보편적 승자를 선언하지 않음 |

기본 추천은 현재 환경에서 기준군과 비교군을 모두 다시 실행하는 짝 비교. 과거 모델·외부 서비스가 재현되지 않으면 당시 환경 그대로의 재현을 주장하지 않는다. 전략 효과를 보려면 모델·effort·과제 입력·시작 상태·평가 기준을 가능한 한 고정한다. reviewer 유무가 변수면 작업 중 리뷰 구성을 달리하되, 종료 후 결과 평가를 공통 기준으로 적용하고 그 평가 비용은 전략 수행 비용과 분리한다.

원 작업 완료 사실은 실험 종료 기준을 정의할 근거다. 정답 코드와 동일한 diff를 만드는 것이 기본 성공 기준은 아니다. 요구 충족·검사·동작·품질을 평가한다. 최종본을 읽고 설계를 개선한 root의 편향, 이미 과제를 수행한 세션의 학습 효과도 기록한다. 비교군 실행 순서를 교차하거나 fresh session을 사용한다. 한 과제에서 우수했던 전략은 그 과제의 결과이며, 반복 횟수만 늘려 다양한 작업에 대한 검증으로 대신하지 않는다.

## 3. 과거 상태에서 재수행

현재 checkout을 reset하거나 사용자 변경을 stash하지 않는다. root의 현재 checkout은 실험 기록 보관에 사용한다. 각 군은 base의 별도 worktree/checkout에서 시작하고 공유 수정·DB·산출물·캐시는 설계에 맞춰 분리한다.

```sh
# hash는 검증한 전체 commit ID, 경로/브랜치는 실험별 고유 이름
 git worktree add -b ept/<id>/baseline .worktrees/ept-<id>-baseline <base_commit>
 git worktree add -b ept/<id>/candidate .worktrees/ept-<id>-candidate <base_commit>
```

두 군은 동일 시작 tree인지 확인한다. 원 reference 구현을 cherry-pick/merge해서 출발하지 않는다. 실험 시작 시 확보한 요구와 공통 입력만 전달하고 새 attempt/session을 기록한다. 현재 실험용 스킬·prompt를 쓸 경우 base에 포함된 옛 스킬과 혼용하지 않고, 별도 지시 파일의 판·해시를 고정한다. 스킬 복사나 검사 도구 설치로 시작 tree를 수정하면 공통 setup delta를 보존하고 두 군에 동일하게 적용한 실제 시작 tree를 명시한다.

Git이 복원하는 것은 추적된 파일이다. 당시 미커밋 변경·비추적 입력·DB·외부 API·설치 캐시·모델 응답·세션 맥락까지 복원하지 않는다. 없는 입력은 미확보로 기록하고, 공통 fixture/snapshot으로 대체했다면 원 작업과의 차이를 남긴다. 새 모델 응답의 동일성이나 원 실행 시간의 재현을 보장하지 않는다.

군별 실행은 experiment.md의 사건·비용·중단 규약을 따른다. 원 결과/후속 테스트가 base에 없으면 평가용 입력을 별도로 동결한다. 모든 군에 같은 평가를 적용하고, 작업자가 종료 전에 평가 내용을 볼 수 있는지 고정한다. 현재 최신 check를 역사적 checkout에 그대로 적용해 생기는 규약/의존성 오류와 구현 결함을 구분한다. 중간에 평가를 바꾸면 모든 결과를 동일 새 기준으로 재평가하고 이전 판정을 보존한다.

## 4. 결과 보존과 다음 활용

군별 최종 코드·필요한 검증 산출물은 정리 전에 커밋해 full hash와 기준점 대비 diff를 남긴다. **hash만 record에 쓰고 마지막 브랜치를 삭제하면 Git GC 이후 복원되지 않을 수 있다.** ept 전용 영구 ref/tag를 유지하거나 commit들을 포함한 Git bundle을 실험 증거로 보관하고, 별도 checkout에서 복원 가능성을 확인한 뒤 worktree를 제거한다. 원 작업 history와 완료 코드는 그대로 보존한다. 실험 브랜치 결과의 제품 반영은 별도 채택 작업이며 재실험 요청만으로 자동 merge하지 않는다.

record에는 역사적 reference와 새 기준군/비교군 결과를 구분해 연결한다. 재실행의 결과 commit, 스킬/prompt 판, 실행 조건, root 비용, 완료·품질 판정과 한계를 남긴다. 설계·실행·검수·결론은 기존 GNAM chore 이력으로 변화 이유를 보존한다. 실험 당시 파일과 코드가 Git으로 복원되도록 증거를 먼저 고정한다.

다음 일반 작업은 적용 조건이 비슷한 과거 실험을 찾아 전략 선택의 근거로 사용한다. 예: '파일 영역 독립/공통 인터페이스 고정 과제에서 병렬 분할의 통합 비용이 낮았음'. 결과가 누적되면 lore·스킬 정책으로 반영하되 실패·중단·미측정과 반례를 함께 참조한다.

## 제안 예시

요청: `multiagent ept 지난 S2 구현을 단일 agent와 runner 둘로 다시 비교해줘`.

- 복원: S2 변경 전 base, 당시 plan의 S2 요구·완료 조건, 원 merge reference.
- 기준군: 단일 agent가 구현·자체 검사. 비교군: 동일 과제의 독립 영역을 둘로 분할하고 root가 통합.
- 고정: model/effort·입력·런타임·시작 tree·종료 후 공통 평가. 변수: 분할/병렬/통합 구조 묶음.
- 측정: 완료 시간·전체 관측 사용량·root 통합 비용·충돌/재설명·요구 충족·후속 결함.
- 결과: 원 실행은 역사적 참고, 두 재실행을 직접 비교. 예산·중단 조건이 미정이면 값을 포함한 설계안을 제안하고 실행하지 않음.
