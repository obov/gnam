# s3 — S3 호환 첨부 저장소

opt-in 내장 plugin `s3`. 요청 첨부 (specs/request.md) 를 S3 호환 저장소 (AWS S3 · Cloudflare R2 · MinIO · Backblaze B2 등) 에 내용 주소로 보관한다.
저장소 (git) 에는 첨부 줄 (이름 · sha256 · 위치) 만 남는다.

## 설정

gnam.json (커밋됨):

```json
{ "s3": { "endpoint": "https://<account>.r2.cloudflarestorage.com", "bucket": "gnam", "region": "auto", "prefix": "gnam/", "pathStyle": true, "maxBytes": 104857600 } }
```

```text
endpoint    필수. https URL
bucket      필수
region      기본 us-east-1. R2 는 auto
prefix      기본 gnam/. 끝은 /
pathStyle   기본 true (<endpoint>/<bucket>/<key>). false = <bucket>.<endpoint host>
maxBytes    기본 104857600 (100MB). 단일 PUT 상한 5GB 이하
```

자격 (환경 변수, 커밋 금지):

```text
GNAM_S3_ACCESS_KEY_ID · GNAM_S3_SECRET_ACCESS_KEY · GNAM_S3_SESSION_TOKEN (선택)
없으면 AWS_ACCESS_KEY_ID · AWS_SECRET_ACCESS_KEY · AWS_SESSION_TOKEN
```

- 설정 형식 문제 = configProblems (필수 키 · 타입 · endpoint https · prefix 끝 /)
- gnam.json s3 에 자격으로 보이는 키 (accessKey · secret · token 포함) 가 있으면 configProblems
- 미구현: 자격이 없으면 명령은 stderr 에 필요한 변수 이름 · exit 1

## 객체

```text
key        <prefix><sha256 hex>
metadata   x-amz-meta-name = 원래 파일 이름 (URI 인코딩)
type       확장자로 Content-Type. 모르면 application/octet-stream
```

- 미구현: 같은 내용은 한 번만 올린다 (HEAD 로 있으면 생략)

## 명령

```text
gnam run s3 put <file…>               올리고 첨부 줄 출력 (파일마다 한 줄)
gnam run s3 get <ref> [-o <path>]     내려받기. ref = sha256:<hex> · s3://<bucket>/<key>
gnam run s3 url <ref> [--expires <초>] presigned GET URL. 기본 3600, 최대 604800
gnam run s3 check [<rev 범위>]         request 커밋의 s3 첨부가 저장소에 있고 크기가 맞는지 (기본 HEAD 전체)
```

- 미구현: put 출력 = `<이름>  sha256:<hex>  s3://<bucket>/<key>  ← <절대 경로>` (specs/request.md 첨부 줄 그대로)
- 미구현: put 의 파일이 maxBytes 초과 = 그 파일 오류 · 나머지는 계속 · exit 1
- 미구현: get 은 내려받은 내용의 sha256 이 ref 와 다르면 파일을 지우고 exit 1. -o 없으면 현재 디렉터리에 원래 이름
- 미구현: check 는 없는 객체 · 크기 불일치를 `<request hash>  <이름>  <문제>` 로 출력 · exit 1. 모두 있으면 `s3 check: 첨부 N개 확인` · exit 0
- 미구현: 네트워크 · 권한 오류 = stderr 에 HTTP 상태 · S3 오류 코드 · exit 1

## 구현 제약

- 미구현: 런타임 의존성 없음. AWS Signature V4 를 node:crypto · fetch 로 직접 구현 (node · bun)
- 미구현: gnam verify 는 네트워크를 쓰지 않는다. 존재 확인은 check 명령만

## 범위 밖

- Deferred: multipart 업로드 (5GB 초과)
- Deferred: 객체 삭제 · 수명 주기 · 버킷 생성
- Deferred: 클라이언트 측 암호화
